=== what this actually says ===
1. LRU IS FLAT FROM 8 GB TO 64 GB. 36.24% at every one of those sizes - an 8x range
   in which more memory buys exactly nothing. The knee is between 64 and 128 GB, and
   full benefit needs 192 GB.

2. THE LEVER IS POLICY, NOT SIZE. At 64 GB, Belady reaches 61.74% where LRU manages
   36.24%. That 25.5-point gap is available to a better replacement policy at the SAME
   memory. Given the routed-expert set is 1.45 TB and the machine budget is tens of GB,
   this is the more promising direction than buying RAM.

3. THERE IS A HARD CEILING AT 90.00%. The trace touches 10,010 distinct experts, each
   of which must be read at least once. No policy at any capacity beats 90% here.

4. K3's ROUTER MAKES THIS HARDER BY DESIGN. The tech report (2.3.3) trains routing with
   Quantile Balancing specifically to FLATTEN expert usage. Flat usage is what defeats
   an LRU cache, so the weak cache behaviour is a property of the model, not a defect
   in the engine.

CAVEAT, and it matters
   This trace was recorded during a run that re-prefills the whole prefix every step,
   so the same experts are legitimately touched ~68 times. Steady-state incremental
   decode has far less reuse, and its hit rates will be LOWER than this curve suggests.
   Treat these numbers as an upper bound on what caching can do, not a forecast.
